# DazoGallery · React Native

本项目的 Android 子模块。界面与导航由 **React Native 0.88.1 + React 19.3 + TypeScript** 实现，使用原生组件渲染，直接调用项目现有 API。浅色配色沿用网页端，另有完整深色配色，默认跟随系统；更多 → 设置可选择跟随系统 / 深色 / 浅色，登录页和原生对话框同步生效。

## 构建

需要 Node 22.13+（本机使用 Node 24）、JDK 21、Android SDK Platform 37、Build Tools 37.0.0、NDK 27.1.12297006、CMake 3.22.1。Gradle Wrapper 会下载 Gradle 9.4.1。依赖以 `pnpm-lock.yaml` 固定。

```powershell
cd android-app
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
.\gradlew.bat testReleaseUnitTest assembleRelease --max-workers=4
```

APK 位于 `app/build/outputs/apk/release/app-release.apk`，包含 JS / Hermes bundle，安装后无需运行 Metro。默认只包含 ARM64，支持 Android 8.0+；Release 开启 R8 代码优化与资源裁剪，保留 React Native 桥接、视图属性及 GIF / WebP 动图解码的反射入口。单元测试以 Release 为目标。继续使用历史版本的固定签名证书，包名 `com.dazo66.android` 不变，可覆盖升级并保留应用数据。

如需 Fast Refresh 开发，可将 `MainApplication.kt` 中 `useDevSupport` 改为 `BuildConfig.DEBUG`、将 `app/build.gradle` 中 `debuggableVariants` 改为 `['debug']`，再运行 `pnpm start` / `pnpm android`。交付配置默认以独立 APK 为准。

## GitHub 自动打包

[Android APK 工作流](../.github/workflows/android-apk.yml) 会在 `master` / `main` 的 Android 代码或工作流变更后自动运行，也支持在 [Actions](https://github.com/dazo6/DazoServer/actions/workflows/android-apk.yml) 中手动运行。构建先执行类型检查和测试，再生成 ARM64 Release APK。从 Artifacts 下载 `DazoGallery-运行编号`，包含 `DazoGallery.apk`、兼容旧更新器的同内容 `DazoMobile.apk`、两份校验文件及 `update.json`，保留 30 天。R8 映射文件单独保存在 `DazoGallery-symbols-运行编号` 中供崩溃诊断。

主分支和手动构建继续使用仓库 Secret `ANDROID_DEBUG_KEYSTORE_BASE64` 中的既有密钥。Secret 名称沿用历史配置，Release 构建使用相同证书以保持覆盖安装兼容。密钥通过 GitHub 的公钥加密上传，不进入代码仓库、构建日志或 APK 附件。发布脚本检查实际 APK：必须是非调试 DazoGallery、仅包含 ARM64，并且签名指纹与既有版本一致，否则终止发布。PR 使用临时签名供构建验证，不发布更新。若迁移仓库，需要重新配置相同密钥；本地可通过 `DAZO_DEBUG_KEYSTORE` 指定其路径。

主分支的成功构建会发布独立的 `android-build-运行编号` Release。只有五份文件上传完整后才公开该版本；已公开版本不会覆盖，重新运行成功构建也保持已有下载地址与内容。旧版更新器继续使用 `DazoMobile.apk` 地址，手动下载使用 `DazoGallery.apk`，两者字节相同。版本号为 `100000 + 运行编号`，防止旧包被误判为新版本。Android 更新版本不会替换服务端的 GitHub Latest Release。

## 应用内更新

设置 → 应用更新可以手动检查，也可关闭自动检查。默认在启动 / 回到前台时检查，自动检查间隔至少 6 小时；手动检查立即执行。发现新版后自动下载，显示进度并支持取消。更新由应用的前台服务下载，切到后台仍可继续；网络中断后重试支持断点续传。进程被终止后，回到应用会恢复未完成的下载。此下载不会因 Android 网络验证失败而被系统下载服务一直挂起。

1.4.0.21 起，更新仅从当前登录的服务器获取：先读取最新版本及更新描述，再通过鉴权 HEAD 获取安装包元数据，使用同一下载接口获取 APK。检查与下载共用登录 Cookie、主备地址及网络变化重置逻辑，不再调用 GitHub API；凭据不会发送给重定向地址。下载前核对版本、兼容信息和签名指纹，下载后核对包大小、SHA-256、包名、实际版本号 / 名称与已安装应用签名。校验通过后提示安装；首次需要允许安装此来源，实际安装必须由 Android 系统确认。安装保留登录和浏览数据，完成后清理旧安装包；仅保留一个待安装更新，大小上限 256 MiB，不占用图片缓存额度。

登录后可自动或手动检查，登录页显示“登录后可检查更新”。更换账户或服务器会清理原更新任务；后台和冷启动只恢复属于同一登录服务器的下载。更新界面展示服务端的更新描述。旧 GitHub 更新器可通过保留的 Release 获取此迁移版本，升级后改用服务端通道。

## 文件上传

系统文件选择器支持多选，一次最多排队 100 个文件，每个最大 2 GiB。选择后立即回到图库，底部浮动进度条显示整体字节进度和当前文件；点击可查看队列、取消单个文件或重试失败项，关闭队列面板不会停止上传。进度条不改变列表高度，也不阻挡其余区域的操作。

上传由原生 dataSync 前台服务执行，切换 Tab、文件夹、进入大图或退到系统后台均继续；任务固定使用选择时的目录和登录账户。由于服务端每个账户只支持一个分片会话，文件按顺序上传，内存最多保留 512 KiB 文件分片。失败会继续下一个文件，退出登录会取消旧账户的待上传任务；进程被终止的当前文件标记为中断，需明确重试，不盲目重复写入。

URI 读取授权与最多 150 条队列元数据持久化，不复制整份原文件。上传进度更新只重绘进度区域；图库等待本目录队列结束、滚动停止并退出大图后静默刷新，通过原文件锚点恢复位置。

## 服务端发布接口

三个接口均需要现有登录 Cookie；上传还需要超级管理员权限和 `X-CSRF-Token`。

| 接口 | 用途 |
| --- | --- |
| `GET /api/app-updates/latest` | 返回 `data.latestVersion` 与 `data.description` |
| `GET /api/app-updates/{version}/apk` | 按版本下载，支持鉴权 HEAD 与 Range / 206 续传 |
| `POST /api/app-updates` | multipart 字段 `file`、`manifest`、`description`，发布完整 APK |

`manifest` 由本机构建脚本读取实际 APK 的版本、架构和签名后生成；服务端只保留包名、版本、大小、SHA-256、签名指纹、最低系统版本和描述，不依赖其中的 GitHub 地址。下载响应通过 `X-App-*` 头提供这些校验信息。APK 最大 256 MiB，本机脚本直接连接内网服务端上传。

可通过 `app.releases.path` 指定持久化目录，默认 `data/app-releases`。其中 `latest.json` **只有两个字段**：

```json
{"latestVersion":"1.4.0.21","description":"更新描述"}
```

每个版本保存在 `{version}/DazoGallery.apk`，旁边的 `manifest.json` 保存该版本的完整校验信息。先写临时目录、校验大小和 SHA-256，再发布版本目录，最后原子替换 `latest.json`。同版本 APK 和描述不可覆盖；重复推送相同内容可以重试，旧构建不会使最新版本回退。

GitHub Actions 只负责打包和发布 GitHub Release，不连接生产服务器、不持有服务端登录凭据。本机构建与内网发布脚本保存在被 Git 忽略的 `android-app/.local-release/`，永久登录凭据保存在同样被忽略的 `android-app/.env.app-release`；它们不会推送到 GitHub。运行本地 `build-publish.ps1 -Version 1.4.0.N -Description "更新描述"` 会检查类型和测试、构建 ARM64 Release、核验签名和实际版本，再直接向内网服务端上传。`1.4.0.N` 对应 `versionCode=100000+N`，其他命名需显式传 `-VersionCode`。版本号须高于已安装及服务端版本。

会话由现有 `/api/auth/login` 接口按数据库随机盐和 HMAC 签发，没有到期时间。注销该会话、管理员“退出所有会话”或更换签名盐会令它失效，此时需重新签发并替换本机 env。发布凭据不进入源码、APK、产物附件或日志。

## 功能与交互

- 底部主导航：首页 / 画师管理 / 自由画廊 / 更多。历史爬取记录、任务管理、用户管理和账户位于二级页面，依据接口权限显示。
- 每个 Tab 独立保留页面栈；切换 Tab、返回父文件夹或画师列表时保留当前位置。图库上滑时收起标题与控制栏，在任意位置向下回滚一段即重新显示，底部 Tab 始终可切换；进入全屏大图后隐藏 Tab。
- 画师使用紧凑两行卡片，banner 铺在整行背景，文字和图标自带轻阴影，头像保留细边框，不使用大块文字底板。状态以更新时间前的图标表示，不显示类型和独立状态栏；首页与画师页统一显示“上次更新 X 小时前 / X 天前”。首页与画师列表均为无限滚动，自动加载下一批，返回或冷启动恢复加载范围和位置。
- 统一下拉刷新。搜索使用输入防抖；筛选使用底部面板；卡片菜单提供管理操作。运行中的任务自动更新状态。
- 图库采用虚拟化单列流，图片无圆角、无文件名栏，左右与图片之间仅保留 2 dp；按实际比例完整显示。文件操作可通过长按进入。支持文件夹、排序、图片缩放和拖动、横向分页浏览、视频播放、原文件和打包下载、多选后台分片上传、单文件取消及失败重试。大图拖动时显示相邻文件，下方列表同步定位当前文件，关闭大图即可继续阅读。
- 设置按“外观与浏览 → 服务器连接 → 存储与缓存 → 应用更新”分组。“直接显示原图”控制列表是否跳过图片缩略图，视频和文件夹仍使用预览。该选项、居中视频自动播放与默认视频倍率按 Host / 用户保存。
- “居中视频自动播放”默认关闭。开启后，滚动停稳后播放中心视频，点击画面进入大图，声音按钮单独切换静音；每次只挂载一个播放器，离开中心、打开大图、切换 Tab 或进入后台时释放。拖动中不启动新播放器，视频首帧就绪前保留封面。内嵌预览使用 TextureView，全屏保留 SurfaceView。
- 缩略图比例加载后，由原生列表保持可见内容的位置和滚动惯性，避免连续视频行高变化时强制跳转。标题与控制栏仍随滑动方向收起、展开。
- 点击图片后从原位置放大进入大图，关闭时缩回当前图片。原图模式直接复用列表已加载的本地原图及解码缓存，不重复下载；缩略图模式保留现有预览，同时加载原图。未切换图片时关闭大图，精确恢复打开前的位置。
- 视频使用 Media3 ExoPlayer，加载时保持黑色背景和缓冲提示，首次起播与重新缓冲目标为约 2 秒媒体数据，按时间而非固定字节判断；实际还需取得文件索引并完成解码。默认隐藏播放器控制栏，点击画面显示，闲置 2.5 秒自动收起。支持 Range 流式读取和拖动进度；长按画面临时切换到所选倍率的 2 倍，松开恢复，右上角默认倍率会记住。
- 下载由应用的前台服务执行，保留必要的后台进度通知；开始、完成和失败使用轻量 Toast 提示，不弹对话框或发送额外完成通知。新文件保存到系统公共“下载 / DazoGallery”，大图右上角可打开已下载文件；设置不再展示下载目录和历史，文件不随图片缓存清理。旧“下载 / Dazo”中的文件、已有下载记录和 Android 8–9 的 FileProvider 地址继续可用。
- 大图浏览向后预缓存最多 10 张原图，跳过视频和文件夹；原图列表模式也会提前加载。预缓存每次只进行一个后台读取，移动位置后替换待加载队列，关闭页面后停止后续预取，与图片缓存共用容量限制。
- GIF / 动态 WebP 只在可见时播放；大图模式仅播放当前页，相邻页保留静态预览，底层图库暂停动图。切换 Tab 或应用进入后台时暂停，返回后恢复；后续十张预缓存只保存文件，不提前播放动画。
- 画师创建和抓取 / 压缩开关、自由画廊增删改、历史筛选与翻页、任务手动运行、用户权限和会话管理、头像裁剪和账户修改均调用现有接口。
- 导航、筛选、分页、列表位置、图库排序和阅读文件按 Host / 用户隔离保存；图库以文件名锚点和偏移恢复，插入新文件后仍优先定位原文件。

## 本地数据

登录填写主服务器根地址、用户 ID 和密码，可以添加最多 5 个备用根地址；登录后也可在设置中维护。连接失败或读取接口遇到 502 / 503 / 504 时自动尝试备用地址，并继续优先使用可用地址。默认网络切换、断开重连、网络地址 / DNS / 代理变化时重置优先级，下次请求从主地址开始；单纯的网络验证状态变化不反复重试主地址。设置展示实际连接地址。所有配置地址应连接同一服务，共用登录 Cookie 与 CSRF Token；只在主地址与用户维度保存状态和缓存，切换地址不产生另一份浏览记录。

密码不保存；会话 Cookie 通过 Android Keystore 加密，只发送给明确配置的服务器，不发送给外部图片地址或外部重定向。登录可自动切换；新增、删除、上传等请求在内容发出且结果无法确认时不会自动重放。图片、视频和原文件下载使用同一账户路由；流读取中断后可尝试备用地址并从已读取位置继续。

图片文件保存在应用私有缓存目录，最多 **256 MiB**；超过 **30 天未使用**的文件自动清理，超出总量时按最久未使用顺序淘汰。单张图片缓存下载限制 64 MiB。设置可查看用量和主动清理。视频流与用户主动下载不受单张图片缓存大小限制；Android 10+ 通过 MediaStore 保存公共下载，Android 8–9 在获得存储权限后保存到相同目录。文件下载不计入可自动清理的图片缓存。

`src/` 为 React Native 界面、导航与状态；`app/src/main/java/com/dazo66/android/` 为 Android 入口和网络、加密、缓存、上传、图标 / 视频组件。没有 WebView，也没有保留另一套 Java 页面。

应用显示名称和通知统一为 DazoGallery，登录页使用同一图标。启动器图标直接使用提供的 789 × 789 原始图片，放在 `drawable-nodpi` 中，不缩小或重新压缩，并提供 Android 自适应图标。包名与旧版更新地址保持兼容，现有版本可以覆盖升级。
